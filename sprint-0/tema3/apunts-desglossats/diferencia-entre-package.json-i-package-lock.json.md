**Quina diferència hi ha entre package.json i package-lock.json?**

## **`package.json` vs `package-lock.json`**

Quan treballes amb Node.js i instal·les llibreries (com React, Express, etc.), el teu projecte genera dos fitxers relacionats amb les dependències. Molta gent els confon, però fan coses molt diferents.

**`package.json`: la llista de la compra**

`package.json` és el fitxer principal del teu projecte. Conté informació general com el nom del projecte, la versió, i sobretot la **llista de dependències** que necessites. És un fitxer que **tu escrius i edites manualment**.

La clau és que les versions que hi poses poden ser **aproximades**. Per exemple, `"react": "^18.0.0"` vol dir "React versió 18 o qualsevol versió compatible superior". El símbol `^` permet que s'instal·li una versió més nova si existeix.

{  
  "name": "el-meu-projecte",  
  "dependencies": {  
    "react": "^18.0.0",  
    "express": "^4.18.0"  
  }  
}

**`package-lock.json`: el rebut exacte**

`package-lock.json` és generat **automàticament** per npm quan fas `npm install`. No l'has d'editar mai manualment. Guarda les versions **exactes** de totes les llibreries que s'han instal·lat, incloent les dependències de les dependències (les llibreries que usen les teves llibreries).

Si `package.json` diu "compra llet aproximadament d'aquesta marca", `package-lock.json` diu "hem comprat exactament aquesta llet, d'aquesta fàbrica, amb aquest lot de producció".

**Per què importa la diferència?**

Imagina que un company de feina clona el teu projecte i fa `npm install`. Si només existís `package.json`, podria instal·lar versions lleugerament diferents de les teves, causant errors difícils de detectar. Amb `package-lock.json`, npm instal·la **exactament** les mateixes versions que tu tens, garantint que el projecte funciona igual a tots els ordinadors.

**Què fer amb cada un**

`package.json` sempre s'ha de pujar a Git — és la configuració del projecte. `package-lock.json` també s'ha de pujar a Git, tot i que el genera npm automàticament, perquè és el que garanteix que tothom treballi amb les mateixes versions. La carpeta `node_modules` (on es guarden físicament les llibreries) **mai** s'ha de pujar a Git — és molt pesada i es pot regenerar sempre fent `npm install`.
